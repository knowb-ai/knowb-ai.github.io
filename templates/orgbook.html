Design Model

Four independent axes

Every KnowB page, asset, product surface, or brand expression can be specified as channel + palette + theme + style + product vocabulary. The axes compose without forcing every product into the same look.

Palette

{{ macros::fins() }}

Autumn or Gold sets color family, signal hierarchy, surface depth, and contrast.

Channel

{{ macros::fins() }}

Internal, External, or Artistic sets the role and destination of the thing.

Theme

{{ macros::fins() }}

Space-race, Psychedelic, Retrowave, Editorial, Arcade, or Comic sets the world and energy.

Style

{{ macros::fins() }}

60s, 70s, 80s, 90s, or 2000s sets the formal visual grammar and finish.

Internal default

{{ macros::fins() }}

Gold + Space-race + 60s primary + 70s secondary. Space-age workspaces use launch, orbit, dock, relay, command, archive, and recovery vocabulary.

External default

{{ macros::fins() }}

Autumn + Arcade + 80s primary + 90s secondary. Public work uses strong silhouettes, color blocking, title-card clarity, and editorial polish.

Artistic default

{{ macros::fins() }}

Autumn or Gold + Comic or Arcade + 90s primary + 2000s secondary. Characters, avatars, mascots, posters, and illustrations remain palette-independent assets.

Typography is fixed brand infrastructure. Rendering treatments such as pixel-art, line-art, inked-comic, graphic-poster, synth-grid, vector, or 3d are optional finish notes, not additional axes.

Channels

Where the design is used

Channels are roles and destinations, not palettes, themes, or eras.

Internal

{{ macros::fins() }}

Product interfaces, workspaces, hubs, control panels, command decks, cockpits, run views, instrumentation, system maps, and operational references. Shared grammar: internal-facing space age with product-owned vocabulary.

External

{{ macros::fins() }}

Marketing, narrative, promotional material, public websites, publishing, product launches, and outward-facing polish. Shared grammar: arcade-informed clarity with composed editorial energy.

Artistic

{{ macros::fins() }}

Characters, avatars, mascot art, posters, editorial scenes, and other authored visual assets. Artistic construction is independent of palette and can appear inside either destination channel.

Styles

Formal visual grammar

Styles are historical reference frames that control geometry, composition, line treatment, pacing, density, and finish. They are not literal reproductions.

StyleProperties
60sSpace age, optimistic modernism, atomic and aerodynamic forms, clean line art, capsule and orbit geometry, confident reduction, forward motion
70sInstrumentation, dials, gauges, radial systems, analog marks, measured density, tactile control logic, system feedback
80sBold title cards, CRT logic, dramatic diagonals, high-impact framing, chunky display forms, hard transitions, strong first read
90sConsole interfaces, arcade-fighter energy, chunky digital forms, darker contrast, industrial futurism, status-heavy layouts, assertive feedback
2000sTechno, controlled comic pop art, polished gradients, compact digital ornament, sleek interfaces, signal gloss, restrained retro-futurism

Theme is the world. Style is the method. For example, Space-race + 70s means orbital operations expressed through dials and radial systems. Arcade + 80s means public clarity expressed through title cards and dramatic diagonals.

Mission & Manifesto

KnowB AI solves the data management and knowledge fragmentation problem at its root. In the AI era, output quality is tied directly to input clarity. Isolated silos and rigid access hierarchies are no longer acceptable.

We build intelligent knowledge infrastructures that bundle durable storage with intelligent agents and operators, managing context, state, and evolution over time.

In a world of chaotic context, KnowB AI builds knowledge systems that think.

Glossary

Core Concepts

Knowledge Base

{{ macros::fins() }}

A structured, queryable store of contextually rich, durable knowledge. Built for interoperability with AI models, human teams, and agents.

Knowledge Agent

{{ macros::fins() }}

An intelligent system that performs actions, answers questions, manages memory, and evolves the Knowledge Base in real time.

Operators

{{ macros::fins() }}

Lightweight rule-driven tools that handle tagging, summarizing, syncing, or enforcing hygiene and structure in Knowledge Bases.

Context

{{ macros::fins() }}

Everything surrounding a task, thread, or decision: tone, intention, dependencies, entities, and prior steps. Context is both local and portable.

Memory

{{ macros::fins() }}

The accumulated state of what was said, done, asked, answered, linked, or concluded. Memory must be stored, scoped, and revived when needed.

Knowledge OS

{{ macros::fins() }}

A modular stack that lets KBs, Agents, and Operators function together with synchronization, switching, versioning, and recall features.

Components

Two layers, one surface

The page speaks in space-age editorial: calm solids, light type, wide spacing. Everything that signals, alerts or frames art switches to the tailfin arcade layer and sits behind the CRT pass.

Editorial layer

  • Backgrounds, sections, headlines, body copy, navigation and layout
  • Solid surfaces, big radii, the planet horizon and sparse stars
  • Space Grotesk 300 display, tracked one-word kickers, saber lines
  • No tickers, readouts or separator glyphs

Arcade layer

  • Buttons, chips, cabinets, alerts, notifications and art screens
  • Tailfin shape: Googie curves and pixel stairs on opposite corners
  • Fin stairs, hard shadows and a split-colour edge
  • The CRT pass behind every message, never over it

Kickers and saber lines

Accessibility

Accessibility Requirements

All pages and components must meet WCAG 2.2 AA. These rules are non-negotiable.

Contrast

{{ macros::fins() }}
  • Normal text: ≥ 4.5:1, measured with the CRT pass applied
  • Large text (≥24px reg / ≥18.66px bold): ≥ 3:1
  • UI boundaries and focus indicators: ≥ 3:1

Keyboard & Focus

{{ macros::fins(lit=2) }}
  • Full keyboard accessibility for all controls
  • Tailfin buttons show an ivory ring in their own shape; links show a saber outline
  • Skip-to-content link on long pages with persistent nav
  • Semantic landmarks: <main>, proper heading order

Motion

{{ macros::fins(lit=1) }}
  • Respect prefers-reduced-motion on all pages
  • All transitions set to 0.01ms under reduced-motion
  • Tailfin lift and press movement switch off under reduced-motion
  • No flicker, rolling bars or glitch bursts anywhere

CRT Pass Scope

{{ macros::fins(lit=2) }}
  • Cabinets, alerts, notifications and art screens only
  • Never on page backgrounds, headlines, body sections or navigation
  • Every layer paints behind text, never over it
  • Legibility degrades: remove the pass from that component first

Copy & Tone

Writing Guidelines

Public-facing copy must be concrete, operational, and privacy-safe.

Rules

  • Position around capabilities, reliability, and measurable outcomes
  • No em dashes (U+2014). Use commas, semicolons, colons, or short sentences
  • Direct, scannable sentence structure
  • No internal hierarchy labels in public copy
  • Concrete and operational; prefer specifics over hype
  • Privacy-safe language for data collection or crawling features
  • Consistent product naming, capitalization, and punctuation
  • Editorial layers carry no tickers, readouts, or separator glyphs such as // or ||

Do vs. Don't

Do"We ship controlled pilots with measurable delivery milestones."
Don't"We're revolutionizing AI with our groundbreaking platform!"
Do"Context isn't static; it evolves."
Don't"Context isn't static. It evolves." (too fragmented)
